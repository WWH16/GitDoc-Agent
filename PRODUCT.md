# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Public developers who want documentation for a GitHub repository without writing it by hand. They arrive with a repo URL, want readable docs they can download, and want to ask follow-up questions about the code.

Today the only real user is the author, running it locally; the public audience is the target, not yet the reality.

## Product Purpose

GitDoc Agent turns a public GitHub repository into readable documentation with diagrams, and answers questions about that repository's code. Success means a developer pastes a URL, gets a usable `DOCUMENTATION.md`, and gets answers grounded in the repo's own source.

The project is meant to become a hosted product later. It is not one yet.

## Positioning

The work is done by an AI agent inside an n8n automation workflow: it reads the repo, writes the docs, renders diagrams, and indexes the source so Ask can answer with the files it used as sources. Generate and Ask share the same repository, so the docs and the answers come from one pipeline.

## Operating Context

- **Generate:** paste a GitHub URL, start a run, and watch step progress (Checking repository URL, Reading repository files, Writing documentation, Rendering diagrams, Finishing up). A run usually takes a few minutes. The result previews as rendered markdown and downloads as `DOCUMENTATION.md`.
- **Ask:** a chat about one repository, with suggested starter questions and collapsible source file lists per answer. A repository must have been generated once (and so indexed) before Ask knows it.
- **Run history:** the 20 most recent workflow executions with status and timestamps.
- Long waits are normal: Ask answers can take two minutes or more on the free Gemini tier.

## Capabilities and Constraints

- The web app is a React + Vite frontend for the n8n workflow. The same job also has Python frontends (`app.py`, `app_pyqt5.py`, `app_tkinter.py`) next to `doc_agent.py`.
- It runs only with `npm run dev`: the Vite dev proxy adds the n8n webhook token and API key, so the browser never sees them. A production build has no proxy and does not work yet.
- Backend: n8n on port 5678, Gemini for the agent, and Pinecone for the Ask index.
- Live step progress needs n8n's "Save execution progress" setting turned on.
- The progress tracker assumes the latest n8n execution belongs to the current user (single local user).
- **Undecided:** hosting, accounts and authentication, multi-user support, private repositories, pricing and limits. Deployment is planned for later, with no target chosen.

## Brand Commitments

- Name: **GitDoc Agent**. Do not use "GitHub Doc Agent"; GitHub is a trademark and the product must not look official or endorsed by GitHub.
- Logo: the Branch D mark, a git branch cut out of a D, with an orange commit as the agent's work. Masters, usage rules and colours live in `brand/` (`brand/README.md`, generated by `brand/build.py`), which is currently git-ignored.
- The wordmark is custom-drawn lowercase "gitdoc agent". Do not retype it in a font.

## Evidence on Hand

- Real run history from a local n8n instance (visible in the Run history tab).
- No testimonials, user numbers, customers, benchmarks, pricing or press exist. Future work must not invent them.
- No trademark search has been done on the name or logo.

## Product Principles

1. **Grounded over impressive.** Answers and docs come from the repository's own source, and the UI shows where (sources, step progress, execution IDs).
2. **Honest about waiting.** Runs take minutes; the product always shows what is happening, how long it has taken, and what to do if it stalls.
3. **One repo, one pipeline.** Generate and Ask work on the same repository, so the URL carries across tabs.
4. **Secrets stay server-side.** Keys never reach the browser, now or after deployment.
